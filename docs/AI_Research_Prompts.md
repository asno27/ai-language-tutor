# 🔎 다른 AI에게 시키는 자료 조사 프롬프트 모음

ChatGPT·Gemini·Perplexity 등 **웹 검색이 되는 AI**에게 그대로 붙여넣어 쓰는 프롬프트입니다. 결과를 받으면 이 프로젝트(Claude Code)에 붙여넣어 주세요. 링크가 열리는지, 라이선스 페이지에 실제로 그렇게 적혀 있는지 **직접 확인한 뒤** `data/resources.json`·`data/worksheet.json`에 반영합니다.

| 프롬프트 | 목적 |
|---|---|
| **A. 학습지 소재 조사** | 영상/음성 + 스크립트가 있고, **합법적으로 가공해서 쓸 수 있는** 학습지 재료 찾기 |
| **B. 앱·학습지 제작 도움 자료 조사** | 공개 데이터셋·도구·알고리즘·학습 연구 등 만드는 데 도움이 되는 자료 찾기 |

> 사용 팁
> - 한 AI의 답을 그대로 믿지 말고, **서로 다른 AI 2~3곳에 같은 프롬프트**를 돌려서 겹치는 것부터 확인하세요. 한 곳에만 나온 링크는 가짜일 가능성이 있습니다.
> - 아래 프롬프트에는 "열어 보지 못한 것은 `미확인`으로 적어라"는 규칙이 들어 있어, 지어낸 링크를 줄이는 데 도움이 됩니다.
> - 검색 기능이 없는 AI에게 시키면 기억에 의존해 틀린 라이선스를 말하기 쉽습니다. **웹 검색이 켜진 모드**로 시키세요.

## 공통 배경 블록 (두 프롬프트 모두 맨 앞에 붙임)

```
[프로젝트 배경]
나는 한국인 영어 학습자를 위한 무료 웹앱 "AI Language Tutor"를 만들고 있어. 
- 사이트는 공개 GitHub 저장소 + Cloudflare(무료)로 배포돼. 그래서 저장소에 올린 자료는 누구나 볼 수 있고, 
  저작권이 있는 자료의 본문을 복사해서 올리면 안 돼.
- 지금은 영어, 나중에 일본어·스페인어로 확장할 계획이야.
- 주요 기능: 영작 교정, 번역, 사전, 발음 채점(쉐도잉), AI 역할극 회화, 단어장(간격 반복), 
  오늘의 영어 추천, 주제별 예문, PDF 업로드 학습지, 자료실.
- "학습지" 한 개의 형식: ① 유튜브 영상(또는 음성) 1개 ② 그 영상의 대사 중 핵심 단어를 {빈칸}으로 만든 문장 3~5개
  (한국어 해석 + 빈칸 힌트) ③ 소리 내어 따라 읽는 쉐도잉용 문단 1개(한국어 해석 포함).
- 기술 제약: 순수 HTML/JavaScript(빌드 없음), 서버 DB는 Cloudflare D1(SQLite)뿐, 모든 외부 서비스는 무료 등급만 사용.

[반드시 지킬 규칙]
1. 웹 검색으로 실제 페이지를 열어 확인한 것만 "확인"으로 적어. 열어 보지 못했거나 기억에 의존한 것은 반드시 "미확인"이라고 표시해.
   링크를 지어내지 마. 확신이 없으면 빼는 게 낫다.
2. 라이선스는 "그 사이트의 이용약관·라이선스 안내 페이지의 URL"을 근거로 적어. 
   약관 문장을 길게 베끼지 말고(15단어 이하의 짧은 인용만) 네 말로 요약해.
3. 저작권이 있는 자료의 본문(대본, 기사, 교재 내용)을 답변에 옮겨 적지 마. 링크와 설명만.
4. 조사한 날짜(오늘 날짜)를 적고, 사이트 정책이 바뀔 수 있다는 점을 감안해 "마지막 확인 날짜"를 항목마다 적어.
5. 숫자·점수·퍼센트·차트는 **출처 URL이 있을 때만** 써. 출처 없는 점수(예: "적합도 9점", "보존율 81%")를 만들어 그래프로 그리지 마.
   근거 없는 수치가 필요하면 "추정"이라고 쓰고 이유를 적어.
6. "~할 수 있다"는 기술적 주장(예: 어떤 API로 무엇을 가져올 수 있다)은 **공식 문서 URL**을 근거로 달아. 문서에서 확인하지 못했으면 가능하다고 쓰지 말고 "미확인"으로 표시해.
7. 무료이면서 가입·결제 없이 접근 가능한 것만. 유료·로그인 필수·학교/기관 전용은 제외하되, 
   제외한 것은 마지막에 "제외한 것과 이유"로 한 줄씩 적어.
```

## 프롬프트 A — 학습지 소재 조사

```
(위 "공통 배경 블록"을 먼저 붙여넣기)

[요청]
영어 학습지(영상 또는 음성 + 스크립트 + 빈칸 받아쓰기 + 쉐도잉)를 만들 때 
**합법적으로 가공해서 쓸 수 있는 무료 소재 출처**를 찾아줘.

[찾을 대상]
- 영상 또는 음성이 있고, 대사 전체 스크립트(자막 포함)가 공식적으로 제공되는 것
- 가공(문장을 잘라 빈칸 만들기, 한국어 해석 붙이기, 발췌해서 따라 읽기 문단 만들기)이 허용되는 라이선스
  → 우선순위: 퍼블릭 도메인 > CC0 > CC BY > CC BY-SA > (CC BY-NC는 "비영리 앱"이라 가능할 수도 있으니 따로 표시) 
    > CC BY-ND는 가공 금지라 "링크만 가능"으로 분류 > 모든 권리 보유(All rights reserved)는 "링크만 가능"
- 난이도(CEFR A1~C2)가 분명하거나, 일상·뉴스·여행·직장·면접 같은 실생활 주제인 것
- 유튜브에 올라와 있어 우리 앱에서 iframe 임베드로 재생할 수 있으면 더 좋음 (임베드 허용 여부 확인)

[이미 조사한 곳 — 중복 제외, 단 새 정보가 있으면 보완]
VOA Learning English, BBC Learning English, Tatoeba, Simple English Wikipedia, EnglishClub, 
English-grammar.at, UsingEnglish.com, LibriVox, Project Gutenberg, TED(CC BY-ND라 링크만)

[조사할 후보 방향 — 이 밖에도 찾아줘]
1. 미국 정부·공공기관이 만든 영어 영상/음성+스크립트 (퍼블릭 도메인 가능성): NASA, NOAA, 국립공원청, CDC, 
   미 국무부 영어교육 프로그램(예: American English 사이트), 의회도서관 등. "제3자 저작물 예외"도 확인.
2. 크리에이티브 커먼즈로 공개된 영어 교육 영상·팟캐스트 (CC BY / CC BY-SA)
3. 대학·비영리 단체의 오픈 교육 자료(OER): 영어 청취·회화 교재, 대본 포함 강의
4. 오디오북/낭독 + 원문이 함께 있는 퍼블릭 도메인 자료 (쉐도잉용 문단 재료)
5. 아이들·초보자용 쉬운 영어 영상 (A1~A2) 중 라이선스가 명확한 것
6. 저작권 걱정 없이 쓰는 방법: "AI가 만든 오리지널 대화문 + 브라우저 TTS 음성" 방식의 장단점 
   (이 방식에 쓸 만한 무료 음성·대본 생성 방법이 있다면 소개)

[출력 형식]
(1) 표 — 한 줄에 한 출처:
| 출처명 | URL | 형태(영상/음성/텍스트) | 레벨 | 스크립트 제공 | 라이선스 | 라이선스 근거 URL | 
  가공 가능?(예/아니오/조건부) | 유튜브 임베드 | 마지막 확인일 | 확인상태(확인/미확인) | 한 줄 평 |

(2) 가장 추천하는 5곳은 따로 골라서, 각각 
   - 구체적인 예시 콘텐츠 2~3개의 URL (실제로 열어 본 것만)
   - 학습지로 만들 때의 구체적 절차와 주의할 점 (출처 표기 방법 포함)

(3) JSON 배열 — 아래 형식 그대로 (우리 자료실 데이터 형식):
[
  {
    "lang": "en",
    "type": "link",
    "license": "public-domain | cc0 | cc-by | cc-by-sa | cc-by-nc | cc-by-nd | copyright",
    "title": "출처명",
    "desc": "한국어 한두 문장 설명 (무엇이 있고 어떻게 쓰면 좋은지)",
    "level": "기초 | 기초~중급 | 중급 | 중급~고급 | 고급",
    "url": "https://..."
  }
]

(4) 마지막에 "제외한 것과 이유", "내가 확신하지 못하는 부분" 두 목록.
```

## 프롬프트 B — 앱·학습지 제작에 도움이 되는 자료 조사

```
(위 "공통 배경 블록"을 먼저 붙여넣기)

[요청]
위와 같은 앱과 학습지를 더 잘 만들 수 있게 도와줄 **자료·데이터·도구·연구**를 조사해줘. 
각 분야마다 "무료로 쓸 수 있는지, 라이선스는 무엇인지, 우리 앱(순수 JS, 무료 서버리스)에 쓸 수 있는지"를 따져서 추천해줘.

[분야]
1. 공개 언어 데이터
   - 예문·문장 데이터셋 (예: Tatoeba 외에 무엇이 있나), 단어 빈도 목록(예: NGSL 같은 것의 라이선스 확인), 
     CEFR 레벨이 붙은 단어/문법 목록 중 **재배포 가능한 것**, 사전 데이터(Wiktionary 파생 등) 
   - 음성 데이터(Common Voice 등): 우리 앱에서 쓸 수 있는 방법이 있는지
2. 학습 알고리즘·교육 연구
   - 간격 반복 알고리즘 비교(SM-2 vs FSRS 등)와 순수 JavaScript로 쓸 수 있는 오픈소스 구현 (라이선스 포함)
   - 쉐도잉·받아쓰기(딕테이션)·역할극 회화·실수 분석이 어학 학습에 효과가 있다는 연구 결과 
     (논문/리뷰 링크와 한 줄 요약. 결과를 과장하지 말고 한계도 적어줘)
   - 초보자 단계별 커리큘럼 설계 참고: CEFR 공식 기술(Can-do 문장), 언어교육 기관이 공개한 레벨별 목표
3. 발음·음성
   - 브라우저 Web Speech API(음성 인식·합성)의 한국 사용자 환경별 제약(Chrome/Safari/삼성 인터넷), 대안 
   - 발음 평가를 더 정확히 하는 무료 방법(예: 유사 발음 단어쌍 처리, 음소 수준 비교) 
4. 무료 AI·음성 서비스
   - 무료로 쓸 수 있는 LLM API·음성 인식·음성 합성 서비스의 **현재** 무료 한도와 조건(가입 필요 여부, 데이터 학습 사용 여부)
   - 한국어 설명 품질이 좋은 모델 추천 (영어 교정 설명을 한국어로 써야 함)
5. 학습지·교재 설계
   - 좋은 받아쓰기/빈칸 문제를 만드는 원칙(어떤 단어를 비워야 하는가), 쉐도잉 문단 길이·속도 권장
   - 학습 동기를 유지하는 방법(연속 학습일, 하루 목표 등)에 대한 근거 있는 자료
6. 일본어·스페인어 확장 대비 (나중에 쓸 자료)
   - 두 언어의 CEFR/JLPT/DELE 기준 단어·문법 목록, 공개 예문, 음성 인식 정확도 이슈, 문자·띄어쓰기 처리 도구
7. 다른 앱 벤치마킹
   - 무료/오픈소스 어학 학습 앱 중 참고할 만한 기능·UX (이름, URL, 우리가 배울 점 한 줄)

[출력 형식]
분야마다:
- 추천 항목 3~6개 — 이름 / URL / 무엇인지 한 줄 / 라이선스 또는 이용 조건 / 우리 앱에 쓰는 방법 / 
  주의점 / 마지막 확인일 / 확인상태(확인·미확인)
- 그중 "지금 바로 쓸 만한 것 1~2개"를 골라 이유 설명

마지막에 전체를 "우리 앱에 적용하면 효과가 큰 순서"로 상위 10개만 다시 정리하고, 
"내가 확신하지 못하는 부분"과 "서로 다른 출처가 다르게 말하는 부분"을 따로 적어줘.
```

4. 실패한 항목과 이유도 `docs/Worksheet_Sources.md`의 "검증 기록"에 남겨, 같은 후보를 다시 조사하지 않게 합니다.

## 받은 결과를 확인해 보니 (2026-10-31 사례)
